## Abstract

Step-by-step knowledge distillation trains a smaller student model using both task labels and natural-language rationales generated by a larger teacher model. Although rationales can provide useful intermediate supervision, automatically generated rationales are not always reliable. Some rationales predict the wrong label, some are too generic, and others do not clearly connect the input to the answer. Using all generated rationales may therefore introduce noisy supervision into student training.

This paper proposes **Boundary-Aware Rationale Selection**, a rationale filtering method that selects training rationales by considering both rationale quality and example-level difficulty. Instead of scoring each rationale independently, the method groups multiple rationale candidates for the same example, performs weighted voting over their predicted labels or answers, computes the voting margin as a measure of agreement, and assigns each example into an `easy`, `boundary`, or `hard` region. The proposed implementation, `judge_student_boundary_mix_balanced`, keeps rationales from `easy` and `boundary` examples while removing `hard` examples that show weak or unstable multi-source agreement.

Experiments on ESNLI and CommonsenseQA show that the proposed method improves over the baseline on both datasets. On ESNLI, accuracy improves from `83.93` to `84.16`; on CommonsenseQA, accuracy improves from `60.36` to `62.41`. Compared with other rationale selection variants, `judge_student_boundary_mix_balanced` provides the most stable cross-dataset behavior, achieving the strongest CommonsenseQA result while maintaining improvement on ESNLI. These results suggest that selecting rationales from examples with reliable agreement and useful difficulty can improve step-by-step distillation.

## 1. Introduction

Large language models can generate natural-language explanations for many reasoning tasks. These explanations, often called rationales, can be used as intermediate supervision when training smaller student models. In step-by-step distillation, the student model does not only learn the final label or answer; it also learns from the explanatory reasoning generated by a teacher model.

However, not all generated rationales are equally useful. A rationale can be fluent but unsupported by the input. It can mention the correct answer but fail to explain the reasoning path. It can also predict a different label from the gold label, especially in ambiguous or difficult examples. If these rationales are directly used for training, the student may learn noisy reasoning patterns instead of robust task behavior.

Consider an ESNLI example:

```text
Premise: A man is playing guitar on stage.
Hypothesis: A person is performing music.
Gold label: entailment
```

A useful rationale would explain that playing guitar on stage is a form of performing music. A weak rationale might only say that both sentences are about a man. The weak rationale is not completely unrelated, but it does not clearly explain why the hypothesis follows from the premise. This illustrates the central problem of rationale selection: the final label alone is not enough. We also need to determine whether the rationale provides meaningful support for the label.

This work studies the following research question:

```text
Given multiple rationale candidates generated for the same training example,
how can we select a reliable subset that improves student model performance?
```

The proposed answer is to select rationales using example-level agreement and difficulty. If multiple rationale sources agree on the same label or answer, the example is more likely to provide stable supervision. If the agreement is strong, the example is treated as `easy`. If the agreement is moderate but still supports the gold answer, the example is treated as `boundary`, meaning that it may help the student learn decision boundaries. If the agreement is weak, the example is treated as `hard` and removed from the selected training set.

The main method in this paper is:

```text
judge_student_boundary_mix_balanced
```

This method is part of a boundary-based rationale selection family. It selects one high-quality rationale per example from `easy` and `boundary` examples, removes `hard` examples, and balances the resulting training data by label.

The contributions of this paper are:

1. We propose a boundary-aware rationale selection pipeline for step-by-step distillation.
2. We use multi-source weighted voting to measure agreement among rationale candidates.
3. We define voting margin as an example-level confidence signal and use it to assign examples into difficulty regions.
4. We select rationales from `easy` and `boundary` examples while filtering out unstable `hard` examples.
5. We evaluate the method on ESNLI and CommonsenseQA and show improvement over the baseline on both datasets.

## 2. Related Work

### 2.1. Knowledge Distillation

Knowledge distillation transfers knowledge from a larger teacher model to a smaller student model. Traditional distillation often trains the student using teacher logits, soft labels, or task predictions. The goal is to preserve useful teacher behavior while reducing model size or inference cost.

In this work, the supervision is not limited to the final label. The student also receives rationales generated by a teacher or rationale-producing source. This places the work closer to explanation-based or step-by-step distillation.

### 2.2. Step-by-Step Distillation

Step-by-step distillation uses natural-language reasoning steps as additional supervision. Instead of training only on input-output pairs, the student learns from input-rationale-output examples. This can help smaller models perform reasoning tasks more effectively because the rationale provides intermediate structure.

However, the effectiveness of this approach depends heavily on rationale quality. If the rationale is noisy, the student may learn misleading reasoning patterns. This motivates rationale selection before training.

### 2.3. Rationale Quality and Filtering

Rationales can be evaluated from several perspectives. A good rationale should be consistent with the predicted label, grounded in the input, concise enough to be learnable, and explicit enough to teach the target reasoning relation. Some rationale selection approaches score individual rationales, but this may ignore the relationship between multiple rationales generated for the same example.

The proposed method differs from single-rationale scoring by considering multi-source agreement. Instead of asking only whether a rationale looks good, the method also asks whether several rationale sources support the same answer for the same example.

### 2.4. Data Filtering and Curriculum Learning

Training data quality affects model performance. Data filtering removes noisy examples, while curriculum learning organizes training examples by difficulty. Boundary-aware rationale selection is related to both ideas. It removes examples whose rationale sources disagree too strongly and keeps examples that are either reliable (`easy`) or useful for learning decision boundaries (`boundary`).

The method does not simply keep the easiest examples. It keeps easy examples for clean supervision and boundary examples for useful contrast near the decision boundary.

## 3. Task and Data

### 3.1. ESNLI

ESNLI is a natural language inference task. Each example contains a premise, a hypothesis, and a label:

```text
entailment
neutral
contradiction
```

The goal is to determine whether the hypothesis is logically supported by, unrelated to, or contradicted by the premise.

Example:

```text
Premise: A young man wearing a backpack and dark glasses approaches the brick building.
Hypothesis: The young man has glasses on his face.
Label: entailment
```

### 3.2. CommonsenseQA

CommonsenseQA is a multiple-choice question answering task. Each example contains a question and several answer choices. The model must select the most plausible answer based on commonsense knowledge.

Example:

```text
Question: Susan was playing games with her five year old son Tim. She played them because they were designed to help him with something. What might they help a child with?
Choices: learning, competitiveness, losing, winning, relaxation
Answer: learning
```

### 3.3. Rationale Candidate Sources

For each example, we collect rationale candidates from multiple rationale styles or sources:

```text
neutral
contrastive
historical
comparative
causal
consensus
if_else
```

Each candidate contains:

| Field | Description |
|---|---|
| `premise` | Input text, question, or context |
| `hypothesis` | Hypothesis or answer choices |
| `rationale` | Natural-language explanation |
| `LLM_answer` | Label or answer predicted by the rationale source |
| `judge_source` | Rationale source/style |

The purpose of using multiple sources is to create several views of the same example. These views allow the method to measure whether different rationales agree on the same label or answer.

## 4. Method: Boundary-Aware Rationale Selection

### 4.1. Overview

The proposed pipeline selects rationales in nine steps:

1. Collect rationale candidates from multiple sources.
2. Group candidates that belong to the same example.
3. Normalize labels or answers.
4. Perform weighted voting among candidates.
5. Compute the vote margin.
6. Score each rationale candidate.
7. Assign the example to a boundary band.
8. Select rationales from allowed bands.
9. Balance the selected dataset by label.

The main implementation is:

```text
judge_student_boundary_mix_balanced
```

The method keeps:

```text
easy + boundary
```

and removes:

```text
hard
```

The pipeline diagram used in the project is:

```text
assets/boundary_family_pipeline.svg
```

### 4.2. Grouping Candidates by Example

Because rationale candidates come from different source files, the first step is to group candidates that describe the same original example. The method creates an example key by normalizing the input texts:

```text
example_key = normalize(premise) + "</s>" + normalize(hypothesis)
```

For ESNLI, `premise` and `hypothesis` are the NLI sentence pair. For CommonsenseQA, the premise corresponds to the question and the hypothesis stores the answer choices.

Normalization removes extra whitespace, strips leading and trailing spaces, and converts text into a consistent format for matching. This step is necessary because the same example may appear in multiple rationale files with small formatting differences.

After grouping, each example can have up to seven candidates, one from each rationale source.

### 4.3. Source Prior

The method uses a source prior to weight votes from different rationale sources. The source prior is a manually defined compatibility weight between:

```text
rationale style/source
```

and:

```text
label or answer type
```

The prior is not learned from training data and is not taken from the original step-by-step distillation paper. It is also not random. It is a hand-defined inductive bias that encodes the relative relationship between rationale style and label type.

For ESNLI, the prior is label-dependent. For example, `historical` and `consensus` rationales are treated as more compatible with `entailment`, while `if_else` is treated as more compatible with `neutral`, and `comparative` or `contrastive` rationales are treated as more compatible with `contradiction`.

#### 4.3.1. ESNLI Source Prior Values

| Label | historical | consensus | contrastive | causal | neutral | if_else | comparative |
|---|---:|---:|---:|---:|---:|---:|---:|
| entailment | 1.00 | 0.98 | 0.95 | 0.92 | 0.88 | 0.74 | 0.70 |
| neutral | 0.72 | 0.82 | 0.90 | 0.84 | 0.96 | 1.00 | 0.99 |
| contradiction | 0.74 | 0.84 | 0.99 | 0.97 | 0.89 | 0.70 | 1.00 |

#### 4.3.2. CommonsenseQA Source Prior Values

For CommonsenseQA, the source prior is answer-source dependent but not label-class dependent:

| Source | Prior |
|---|---:|
| causal | 1.000 |
| if_else | 0.990 |
| neutral | 0.980 |
| contrastive | 0.975 |
| historical | 0.940 |
| consensus | 0.840 |
| comparative | 0.800 |

The prior should be described carefully in the final paper:

```text
We define source priors as manually specified compatibility weights between rationale styles and predicted labels. These priors are not learned parameters; instead, they encode an inductive bias about which rationale styles are more suitable for each label type. Their usefulness is evaluated empirically through downstream student performance.
```

### 4.4. Weighted Voting

Each rationale candidate predicts a label or answer. A simple voting method would count each source equally. However, the proposed method uses source priors to perform weighted voting.

For a label `y`, the weighted score is:

```text
score(y) = sum prior(source_i, y)
           for all candidates i whose predicted label is y
```

The voted label is the label with the highest weighted score:

```text
voted_label = argmax_y score(y)
```

Example:

| Source | Predicted label | Weight |
|---|---|---:|
| historical | entailment | 1.00 |
| consensus | entailment | 0.98 |
| causal | entailment | 0.92 |
| if_else | neutral | 1.00 |
| comparative | contradiction | 1.00 |

Then:

```text
score(entailment) = 1.00 + 0.98 + 0.92 = 2.90
score(neutral) = 1.00
score(contradiction) = 1.00
```

The voted label is:

```text
entailment
```

### 4.5. Vote Margin

The vote margin measures how clearly the winning label beats the second-best label:

```text
voted_label_margin = winner_score - runner_up_score
```

This value is important because the winning label alone does not tell us whether the decision is stable. A label that wins by a large margin indicates stronger agreement. A label that wins by a very small margin indicates an unstable or ambiguous example.

Interpretation:

| Margin | Meaning |
|---|---|
| High | Many sources support the same label or answer |
| Medium | The example has useful signal but is near the decision boundary |
| Low | Sources disagree strongly; the example may be noisy |

### 4.6. Boundary Band Assignment

After voting, each example is assigned to a difficulty band.

For ESNLI:

```text
easy:
  voted_label_margin >= 2.1
  and label_counts[training_label] >= 5

boundary:
  voted_label_margin >= 1.1
  and label_counts[training_label] >= 2

hard:
  otherwise
```

For CommonsenseQA:

```text
easy:
  voted_label_margin >= 2.4
  and label_counts[gold_answer] >= 5

boundary:
  voted_label_margin >= 1.6
  and label_counts[gold_answer] >= 3

hard:
  otherwise
```

The intuition is:

| Band | Description | Used in `boundary_mix` |
|---|---|---|
| `easy` | Strong agreement and high vote margin | Yes |
| `boundary` | Moderate agreement; useful near the decision boundary | Yes |
| `hard` | Weak agreement or unstable prediction | No |

The method treats `hard` as an example-level property. It does not mean that one rationale is linguistically difficult. It means that the group of rationale sources does not provide sufficiently stable support.

### 4.7. Candidate Quality Scoring

Within each example group, the method still needs to choose the best rationale candidate. Candidate quality is computed using several signals:

| Signal | Purpose |
|---|---|
| `source_prior` | Whether the rationale source is compatible with the target label |
| `overlap_score` | Whether the rationale uses words related to the input |
| `teaching_hits` or cue hits | Whether the rationale contains useful explanatory cues |
| `explicit_label` or explicit answer | Whether the rationale states the target label/answer |
| `format_bonus` | Whether the rationale has clear answer format |
| `brevity` | Whether the rationale length is reasonable |
| `agreement_count` | How many sources support the same label/answer |
| `agreement_ratio` | Fraction of sources supporting the same label/answer |
| `vote_margin` | Strength of the winning label/answer |

For ESNLI, the score follows this structure:

```text
quality =
    source_prior
  + 0.55 * overlap_score
  + 0.22 * teaching_hits
  + 0.20 * explicit_label
  + format_bonus
  + brevity
  + 0.12 * agreement_count
  + 0.08 * agreement_ratio
  + 0.03 * vote_margin
```

For CommonsenseQA, the score uses a similar structure but with CQA-specific weights:

```text
quality =
    source_prior
  + overlap_weight * support_overlap
  + agreement_weight * agreement_count
  + 0.12 * agreement_ratio
  + margin_weight * vote_margin
  + 0.20 * explicit_answer
  + 0.08 * cue_hits
  + 0.12 * preferred_source_bonus
  + brevity
```

The score is not a learned neural judge. It is a rule-based judge designed to prefer rationales that are source-compatible, grounded in the input, explicit, concise, and supported by multi-source agreement.

### 4.8. Final Selection

The final selection rule for the proposed method is:

```text
allowed_bands = {"easy", "boundary"}
max_per_example = 1
```

This means:

- keep only `easy` and `boundary` examples
- remove `hard` examples
- select one rationale per example
- balance selected examples across labels where applicable

For ESNLI, balancing produces equal label counts:

```text
entailment: 3018
neutral: 3018
contradiction: 3018
```

### 4.9. Boundary Family Variants

The boundary family includes three related methods:

| Method | Bands | Max rationales per example | Purpose |
|---|---|---:|---|
| `judge_student_boundary_mix_balanced` | easy + boundary | 1 | Main method, stable across datasets |
| `judge_student_boundary_bridge_balanced` | easy + boundary + bridge | 2 | Adds a second diverse rationale when available |
| `judge_student_boundary_specialist_balanced` | boundary + bridge | 2 | Focuses on selected specialist sources; ESNLI only |

The main paper focuses on `boundary_mix` because it is simpler than `boundary_bridge`, avoids adding many secondary rationales, and shows stronger cross-dataset stability.

```text
It selects rationales based on agreement and useful example difficulty.
```

This is easier to justify in the thesis than a purely hybrid or fusion-based method, because the selection mechanism directly connects to the research question.

## 7. Analysis

### 7.1. Why Boundary Mix Works

`boundary_mix` works because it avoids two extreme choices:

1. It does not use all generated rationales.
2. It does not keep only the easiest examples.

Instead, it keeps:

```text
easy examples + boundary examples
```

Easy examples provide clean supervision. Boundary examples provide useful training signals near the decision boundary. Hard examples are removed because they show weak agreement or unstable support.

This makes the selected training set both clean and informative.

### 7.2. Why Not Use Hard Examples?

In this method, `hard` means that the group of rationale sources does not provide enough agreement. A hard example may contain:

- conflicting predicted labels
- weak vote margin
- too few sources supporting the gold label or answer
- rationales that do not clearly support the target

Therefore, removing hard examples is a noise-control decision rather than an attempt to avoid all difficult reasoning.

Example hard ESNLI case before filtering:

| Field | Value |
|---|---|
| Premise | A group of construction workers are working. |
| Hypothesis | A group of guys outside. |
| Selected label | neutral |
| Source | contrastive |
| Agreement count | 3 |
| Vote margin | 0.01 |

Rationale:

```text
The most likely answer is neutral. This is because the hypothesis is not necessarily true or false based on the premise. A group of guys outside could be construction workers, but they could also be doing something else.
```

This example is not obviously useless, but the margin is extremely small. The source group is almost tied, so the method treats it as unstable for training.

### 7.3. Why Keep Boundary Examples?

Boundary examples are useful because they are not completely obvious but still have enough support. They can teach the student subtle distinctions.

Example ESNLI boundary case:

| Field | Value |
|---|---|
| Premise | Two men, one standing and one seated on the ground are attempting to wrangle a bull as dust from the action is being kicked up. |
| Hypothesis | A rodeo clown tries to save a rider from a bull. |
| Selected label | neutral |
| Source | consensus |
| Agreement count | 4 |
| Vote margin | 1.11 |

Rationale:

```text
The commonly agreed-upon answer is neutral. The hypothesis is neither entailed nor contradicted by the premise. It is possible that the two men are rodeo clowns trying to save a rider from a bull, but it is not necessarily the case.
```

This rationale is useful because it explains why the hypothesis may be plausible but not guaranteed by the premise. That is exactly the kind of distinction a student model needs to learn for neutral examples.

Example CommonsenseQA boundary case:

| Field | Value |
|---|---|
| Question | Where did his wife ask him to look first when he complained of missing deodorant? |
| Choices | grocery store, nightstand, armpits, own bathroom, medicine chest |
| Selected answer | medicine chest |
| Source | causal |
| Agreement count | 4 |
| Vote margin | 1.61 |

Rationale:

```text
The correct answer is medicine chest. His wife asked him to look first in the medicine chest because that is where he usually keeps his deodorant.
```

This example is near the boundary because several choices are plausible locations. The rationale helps connect the answer to commonsense household storage.

### 7.4. Why Source Prior Is Reasonable but Limited

The source prior gives the method an inductive bias. It encodes the idea that different rationale styles are more useful for different label types. For example, contrastive rationales are naturally suited to contradiction because they emphasize differences, while if-else rationales are suitable for neutral cases because they often express uncertainty or missing conditions.

However, the prior is still manually defined. It should not be presented as a learned or statistically calibrated value. Its role is to guide selection, not to prove source reliability by itself.

A strong final paper should include an ablation comparing weighted voting with equal voting. This would show whether the manually defined prior contributes to the final performance.

### 7.5. Why Boundary Mix Is Preferred over Boundary Bridge

`boundary_bridge` adds a second rationale when a sufficiently different rationale is available. This increases training coverage and may explain the strong ESNLI score. ESNLI often benefits from multiple logical views of the same sentence pair.

However, CommonsenseQA appears more sensitive to additional rationale noise. Many commonsense questions have answer choices that are semantically close, and adding a second rationale can introduce extra associations that do not consistently improve the student.

Therefore, `boundary_mix` is preferred as the proposed method because it is simpler and more stable:

```text
one selected rationale per example
easy + boundary examples only
balanced output
improvement on both datasets
```

## 8. Ablation Plan

The current draft does not yet include completed ablation experiments. However, ablation is important because it can answer questions about which part of the method matters most.

Recommended ablations:

| Ablation | Purpose |
|---|---|
| Equal vote instead of weighted vote | Test whether source prior helps |
| Remove overlap score | Test whether input grounding matters |
| Easy only | Test whether boundary examples add value |
| Boundary only | Test whether boundary examples are sufficient |
| Easy + boundary + hard | Test whether hard examples introduce noise |
| Remove label balancing | Test whether balanced selection matters |
| One source only | Test whether multi-source agreement matters |

The most important ablation is:

```text
weighted vote vs equal vote
```

This directly addresses the question:

```text
Why do we define prior values?
```

Possible interpretation:

- If weighted vote is better, the source prior is useful.
- If equal vote is similar, the method is robust and the prior acts only as a soft preference.
- If equal vote is better, the manual prior should be replaced or learned from validation data.

## 9. Discussion

### 9.1. Main Finding

The main finding is that rationale selection should consider example-level agreement, not only individual rationale quality. A rationale can look good by itself, but if other sources strongly disagree on the answer, the example may be unstable for training.

Boundary-aware filtering provides a simple way to combine rationale quality and example difficulty.

### 9.2. Cross-Dataset Behavior

The proposed method improves both ESNLI and CommonsenseQA. The improvement on CommonsenseQA is larger, which may indicate that rationale filtering is particularly valuable when the task depends on commonsense associations and answer choices.

The stronger ESNLI performance of `boundary_bridge` suggests that different datasets may prefer different amounts of rationale diversity. ESNLI can benefit from secondary logical views, while CommonsenseQA may benefit more from a single clean rationale.

### 9.3. Practical Advantage

The method is easy to implement. It does not require training an additional judge model. It only requires:

- multiple rationale candidates
- predicted labels or answers
- source names
- rule-based scoring
- downstream evaluation

This makes the method practical for settings where rationale candidates are available but additional model training is expensive.

---

## 10. Limitations

This work has several limitations.

First, the source prior is manually defined. Although it is motivated by the relationship between rationale style and label type, it is not learned from data. A stronger version of the method could learn source weights from a validation set.

Second, the thresholds for `easy`, `boundary`, and `hard` are rule-based. They may not be optimal for all datasets or model architectures.

Third, the method evaluates rationale usefulness indirectly through downstream accuracy. It does not directly prove that the selected rationales are faithful explanations.

Fourth, the current comparison is based on available performance results, but the final paper should verify training details such as random seeds, model backbone, number of runs, and hyperparameters.

Fifth, the current draft does not yet include ablation results. Ablation is important for separating the effect of weighted voting, overlap scoring, boundary filtering, and label balancing.

---

## 11. Future Work

Future work can improve the method in several directions.

First, source priors can be learned automatically from validation performance rather than manually defined. This would make the method more data-driven and easier to justify.

Second, threshold values for band assignment can be tuned on a validation set.

Third, the rule-based judge score can be replaced or augmented by a learned rationale judge.

Fourth, faithfulness evaluation can be added to test whether selected rationales truly reflect the model's decision process.

Fifth, the method can be tested on additional reasoning datasets to evaluate generalization beyond ESNLI and CommonsenseQA.

---

## 12. Conclusion

This paper proposes Boundary-Aware Rationale Selection for step-by-step knowledge distillation. The method groups multiple rationale candidates for the same example, measures multi-source agreement using weighted voting, computes vote margin, assigns examples into difficulty bands, and selects rationales from `easy` and `boundary` examples while removing `hard` examples.

The main implementation, `judge_student_boundary_mix_balanced`, improves over the baseline on both ESNLI and CommonsenseQA. It increases ESNLI accuracy from `83.93` to `84.16` and CommonsenseQA accuracy from `60.36` to `62.41`. Although `boundary_bridge` achieves higher ESNLI accuracy, `boundary_mix` is more stable across datasets and achieves the best CommonsenseQA result among the compared methods.

These results suggest that rationale selection benefits from considering not only the quality of individual rationales, but also the agreement structure among multiple rationale sources and the difficulty region of each example.
